# Lab — setup e operação (Empresarial GRNO)

> Última revisão: **2026-07-27** · Índice: [README.md](README.md)

Guia para ambiente de **lab** (WSL ou Debian de desenvolvimento): usuário típico **`rcard`**, units systemd com sufixo **`-lab`**, dados SIR via snapshot (`db:import`) ou ingest opcional.

**Produção** (usuário `datacenter`, units sem `-lab`): [2026-07-26-deploy-producao.md](2026-07-26-deploy-producao.md).

**Não** misture units lab e prod no mesmo host (mesma porta **3003** e mesmos `states/` do ingest).

---

## 1. Pré-requisitos

| Item                | Notas                                                |
| ------------------- | ---------------------------------------------------- |
| **Node.js 20+**     | `node -v` / `npm -v`                                 |
| **MariaDB/MySQL**   | Banco SIR `claroEmpresarial` + leitura HFC `hfc-sls` |
| **Git**             | Repo em `/usr/local/empresarial`                     |
| **Usuário `rcard`** | Dono típico do lab; units `*-lab*` usam `User=rcard` |
| **Rede GRB/Critel** | Opcional no lab; necessário para TELNET e gráficos   |

Todos os comandos abaixo assumem:

```bash
cd /usr/local/empresarial
```

---

## 2. Variáveis de ambiente

```bash
cp .env.example .env.local
# Editar: SIR_DB_*, HFC_DB_*, AUTH_SECRET, APP_PUBLIC_URL
# Opcional lab: GRB_BASE_URL, CRITEL_BASE_URL

cd workers/sir-ingest
cp .env.example .env
# Editar: SIR_DB_* (iguais à raiz), SISTEMA_* se for rodar ingest
cd ../..

npm install
npm run env:check
```

- Fonte de verdade: `.env.example` e `workers/sir-ingest/.env.example`.
- Detalhes das chaves: [2026-07-26-operacao.md §4](2026-07-26-operacao.md#4-variáveis-de-ambiente).
- Align: `npm run env:check` · skill `.cursor/skills/emp-align-env/SKILL.md`.

**Não** copie secrets de lab para produção (nem o contrário).

## 3. Banco SIR

No lab é comum carregar um **snapshot** de desenvolvimento. Em produção os dados vêm só do ingest.

```bash
cd /usr/local/empresarial
npm run db:bootstrap          # cria DB + usuário (sudo mariadb no Debian/WSL)
npm run db:migrate
npm run db:import             # snapshot dev — NÃO use em prod
# atalho equivalente: npm run db:setup
npm run db:seed-staff         # único usuário staff (interativo)
```

Em Debian/Ubuntu use **`sudo mariadb`** no bootstrap (`ERROR 1698` com `mariadb -u root -p`).

Skill de banco: `.cursor/skills/emp-db-setup/SKILL.md`.

## 4. Next.js (UI + BFF)

### Opção A — desenvolvimento interativo

```bash
cd /usr/local/empresarial
npm run dev                   # http://127.0.0.1:3003
```

### Opção B — unit systemd lab

```bash
cd /usr/local/empresarial
sudo cp deploy/systemd/lab/empresarial-next-lab.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now empresarial-next-lab
```

A unit lab roda `npm run dev` (hot reload). Conferir: `systemctl status empresarial-next-lab`.

## 5. Worker SIR (opcional)

Só necessário se quiser ingest live no lab (em vez de confiar só no `db:import`).

```bash
cd /usr/local/empresarial/workers/sir-ingest
npm install
export PLAYWRIGHT_BROWSERS_PATH=/usr/local/empresarial/workers/sir-ingest/.playwright-browsers
npm run install:browsers
cd ../.. && npm run env:check
```

### Manual

```bash
cd /usr/local/empresarial/workers/sir-ingest
npm run start:ral   # e/ou start:rec
```

### Systemd lab

```bash
cd /usr/local/empresarial
sudo cp workers/sir-ingest/deploy/systemd/lab/*.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now sir-ingest-ral-lab sir-ingest-rec-lab
```

Arquivos `states/*.json` são runtime local e **não entram no git**. Detalhes: [workers/sir-ingest/README.md](../workers/sir-ingest/README.md).

## 8. Lab vs produção

| Aspecto            | Lab                                    | Produção                                            |
| ------------------ | -------------------------------------- | --------------------------------------------------- |
| Usuário systemd    | `rcard`                                | `datacenter`                                        |
| Units Next         | `empresarial-next-lab` (`npm run dev`) | `empresarial-next` (`npm run start` + build)        |
| Units ingest       | `sir-ingest-*-lab`                     | `sir-ingest-ral` / `sir-ingest-rec`                 |
| Units Telegram     | `sir-telegram-*-lab`                   | `sir-telegram-ops` / `sir-telegram-datacenter`      |
| Dados SIR iniciais | `db:import` (snapshot) ok              | **Proibido** `db:import` — só ingest                |
| Secrets            | Locais do lab                          | Próprios; nunca copiar do lab                       |
| Checklist          | Este documento                         | [deploy-producao.md](2026-07-26-deploy-producao.md) |

## 9. Atualização no lab

```bash
cd /usr/local/empresarial
git pull origin main
npm install
# se mudou migrations:
npm run db:migrate
# se usa unit Next lab: restart; se npm run dev: reinicie o processo
sudo systemctl restart empresarial-next-lab   # se aplicável
```

Delta manual (migrations novas, GRB, Telegram): [operacao-prod/README.md](operacao-prod/README.md) — aplicar seção **Passos — Lab** e marcar status.

| O que mudou                    | Ação extra                                                             |
| ------------------------------ | ---------------------------------------------------------------------- |
| `workers/sir-ingest/` (scrape) | `cd workers/sir-ingest && npm install` + restart `sir-ingest-*-lab`    |
| `workers/sir-ingest/telegram/` | `telegram/venv/bin/pip install -r requirements.txt` + restart bots lab |
| `.env.example`                 | Alinhar `.env.local` / worker `.env`; `npm run env:check`              |
