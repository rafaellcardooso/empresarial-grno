## 1. Pré-requisitos

- Linux (dev WSL ou servidor Debian)
- **Node.js 20+** e npm
- **MariaDB/MySQL** — banco SIR `claroEmpresarial` + leitura `hfc-sls` (BSOD)
- Repo em `/usr/local/empresarial`
- Rede interna para **GRB** e **Critel** (HTTP para `200.255.253.12` ou equivalente)
- Worker SIR: **Playwright/Chromium** (`workers/sir-ingest`)

---

## 2. Arquitetura

| Camada                  | Local                                              | Escreve DB?               |
| ----------------------- | -------------------------------------------------- | ------------------------- |
| UI + BFF (App Router)   | `app/(shell)/`, `app/api/`, `components/`, `lib/`  | Não (SIR + HFC read-only) |
| Tratativas (workflow)   | `app/api/tratativas/`, `lib/queries/tratativas.ts` | Sim → MySQL SIR           |
| Queries / pools         | `lib/db/`, `lib/queries/`, `lib/models/`           | Leitura SIR/HFC           |
| Migrations SIR          | `migrations/sir/`, `scripts/db/`                   | DDL + seed dev            |
| Ingest SIR (Playwright) | `workers/sir-ingest/sources/`                      | Sim → `rals` / `recs`     |
| Bot Telegram SIR        | `workers/sir-ingest/telegram/`                     | Não (HTTP → Next `/api`)  |
| Proxy GRB/Critel        | `lib/grb/`, `lib/critel/`, `app/api/grb/`          | Não (HTTP → legado GRB)   |

**Fronteiras:**

- Scrapers **não** rodam dentro do Next.
- Este repo **não escreve** no MySQL `hfc-sls` (enrich BSOD continua no hfc-sls).
- Porta padrão: **3003**.

## 3. Setup — desenvolvimento local

```bash
cd /usr/local/empresarial
cp .env.example .env.local
npm run db:bootstrap          # WSL: cria DB + usuário (sudo mariadb)
npm run db:migrate && npm run db:import   # snapshot dev; ou db:setup
npm run db:seed-staff         # staff único (interativo)
npm run env:check
npm install
npm run dev                   # http://localhost:3003
```

Worker SIR (opcional em dev):

```bash
cd workers/sir-ingest
cp .env.example .env
npm install && npm run install:browsers
cd ../.. && npm run env:check
npm run start:ral   # e/ou start:rec
```

Skill detalhada de banco: `.cursor/skills/emp-db-setup/SKILL.md`.

## 4. Variáveis de ambiente

Fonte de verdade: **`.env.example`** (raiz) e **`workers/sir-ingest/.env.example`**.

Validação: `npm run env:check` (paridade example ↔ local, ordem e comentários; `SIR_DB_*` igual entre Next e worker).

| Bloco     | Chaves                                                                                   | Uso                                                    |
| --------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| MySQL SIR | `SIR_DB_HOST`, `SIR_DB_PORT`, `SIR_DB_USER`, `SIR_DB_PASSWORD`, `SIR_DB_NAME`            | Next (leitura + tratativas) e worker (escrita RAL/REC) |
| MySQL HFC | `HFC_DB_*`                                                                               | Leitura `tbl_inventory_pme` (BSOD)                     |
| App       | `PORT`, `APP_PUBLIC_URL`                                                                 | Next.js                                                |
| GRB       | `GRB_BASE_URL`, `GRB_TELNET_USERNAME`, `GRB_TELNET_PASSWORD`, opcional `GRB_TELNET_ARG0` | Proxy telnet topologia de rede (Basic Auth)            |
| Critel    | `CRITEL_BASE_URL`                                                                        | Gráficos de desempenho de circuitos                    |
| Auth      | `AUTH_SECRET`, `AUTH_SESSION_DAYS`, `APP_TOUR_VERSION`                                   | JWT em cookie HTTP-only                                |

Exemplo GRB/Critel:

```dotenv
GRB_BASE_URL=http://200.255.253.12/grb/topologia_rede/www
GRB_TELNET_USERNAME=matricula
GRB_TELNET_PASSWORD=troque_me
# GRB_TELNET_ARG0=_]C<>:<;@>
CRITEL_BASE_URL=http://200.255.253.12/grb/critel
```

## 7. GRB — TELNET

Fluxo integrado em `/grb` (espelhado do botGrb):

1. **UF / região** → equipamento (catálogo AM/MA/PA ou hostname livre).
2. **Comando** — preset whitelist (`commandPresetId`); o servidor monta o texto, não aceita comando arbitrário.
3. Campos dinâmicos (IP, interface, VRF/VPRN, WORD) conforme o preset.
4. `POST /api/grb/execute` carrega HTML do console GRB, obtém tokens e executa via proxy telnet.
5. Saída exibida na página; apenas a **linha de eco do prompt** é substituída pelo comando enviado (resposta intacta).

### Plataformas

| Plataforma      | Equipamentos                      | Comandos                                                                          |
| --------------- | --------------------------------- | --------------------------------------------------------------------------------- |
| **Nokia SR OS** | Catálogo AM/MA/PA                 | Ping (router-instance VPRN) · STAFF: interfaces + BGP SR OS                       |
| **Cisco IOS**   | Hostname livre / fora do catálogo | Ping (todos) · STAFF: catálogo GRB legado (~95 `sel_cmds`) agrupado por categoria |

Categorias Cisco no select: Ping, Traceroute, Interfaces, BGP, VRF, OSPF, Rotas/CEF, Multicast, ARP, Políticas, WAN/controllers, Plataforma, Show.

### VPRN Nokia

- `GET /api/grb/vprn?eqpto=…` — lista `show service service-using vprn` (service-id + nome).
- Ping usa **nome** (`router-instance PRODUCTION:7776`).
- BGP VPRN STAFF usa **service-id** (`show router 7776 bgp neighbor …`).

### Módulos

| Arquivo                                   | Função                                       |
| ----------------------------------------- | -------------------------------------------- |
| `lib/config/grb-telnet-catalog.ts`        | UF → equipamentos + plataforma               |
| `lib/config/grb-telnet-commands.ts`       | Presets ping + lookup                        |
| `lib/config/grb-telnet-staff-commands.ts` | STAFF Nokia (interfaces, BGP)                |
| `lib/config/grb-telnet-cisco-commands.ts` | Catálogo Cisco derivado de `grb-commands.ts` |
| `lib/config/grb-telnet-ui.ts`             | Rótulos, grupos, preview                     |
| `lib/grb/telnet-vprn.ts`                  | Parse VPRN                                   |
| `lib/grb/execute-telnet.ts`               | HTTP GRB + execução preset                   |
| `lib/grb/sanitize-telnet-output.ts`       | Eco do prompt                                |
| `components/grb/GrbTelnetPanel.tsx`       | UI principal                                 |
| `components/grb/GrbTelnetVprnField.tsx`   | Lista VPRN Nokia                             |

Staff pode abrir o console legado completo via `/api/grb/console` (HTML patched).

`id_rede` fixo em **0**. Presets legados espelhados em `lib/config/grb-commands.ts` (fonte do catálogo Cisco).

## 8. Critel — gráficos de circuito

Fluxo em `/grb/critel`:

1. Usuário informa **designação** (formato `local/tipo/número`, ex.: `itz/ip/01816`).
2. `POST /api/grb/critel/graph` consulta o portal Critel legado:
   - `proc/pesquisa.php` — busca por designação
   - `proc/graficos.php` — metadados + URL do gráfico
   - `proc/graph.php` — PNG (sessão PHP)
3. UI exibe gráfico, período e sumário (média, máximo, percentis).

Código: `lib/critel/`, `components/grb/CritelPanel.tsx`, config em `lib/config/critel.ts`.

## 14. Troubleshooting

| Sintoma                 | Verificação                                                   |
| ----------------------- | ------------------------------------------------------------- |
| GRB/Critel timeout      | Rede até `GRB_BASE_URL` / `CRITEL_BASE_URL`; curl manual      |
| TELNET 403              | Comando restrito a staff; usuários comuns só ping             |
| Critel sem resultados   | Designação no formato `LOC/TIPO/NUM`; maiúsculas normalizadas |
| `api/saude` ERRO SIR    | `.env.local`, `npm run env:check`, `db:migrate`               |
| Worker `rowErrors` alto | Journal RAL/REC; restart após fix de scrape                   |
| UI antiga após pull     | `npm run build && sudo systemctl restart empresarial-next`    |

Erros de deploy e bootstrap: [deploy/README.md](../deploy/README.md#troubleshooting-erros-comuns).
